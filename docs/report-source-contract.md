# KReports 보고서 원천 및 재무제표 주석 기준

## 1. 이 문서의 목적

KReports에서 `사업보고서`, `감사보고서`, `재무제표`, `주석`이라는 표현을
사람마다 다르게 이해하면 같은 회사와 연도를 분석하면서도 서로 다른
원문을 사용하게 됩니다. 이 문서는 어떤 정보를 어느 DART 제출물에서
가져와야 하는지를 하나의 기준으로 정합니다.

이 문서에서 사용하는 전문 용어는 처음 등장할 때 괄호로 설명합니다.

## 2. 보고서의 정의

### 2.1 사업보고서

사업보고서(Business Report, 회사가 사업·위험·지배구조 및 여러 법정
공시사항을 종합해 제출하는 보고서)는 다음 정보의 기본 원천입니다.

- 사업의 내용과 수익구조
- 제품·서비스와 매출·매입 구조
- 원재료와 생산설비
- 연구개발
- 위험요인
- 주요 계약
- 종속기업·관계기업에 관한 사업상 설명
- 지배구조와 그 밖의 법정 공시사항

사업보고서에 재무제표나 주석과 유사한 내용이 포함될 수 있지만, KReports는
이를 재무제표 주석의 기본 원천으로 사용하지 않습니다.

### 2.2 감사보고서 패키지

감사보고서 패키지(Audit Report Package, DART 감사보고서 제출물 전체)는
감사인의 의견이 적힌 본문 몇 페이지만 의미하지 않습니다. 다음을 모두
포함합니다.

- 독립된 감사인의 감사보고서
- 감사의견과 감사의견 근거
- 핵심감사사항(KAM, 감사인이 해당 감사에서 특히 중요하다고 판단한 사항)
- 계속기업 관련 문단
- 강조사항과 기타사항
- 첨부된 감사대상 재무상태표
- 손익계산서 또는 포괄손익계산서
- 현금흐름표
- 자본변동표
- 재무제표 주석 전체
- 유의적인 회계정책
- 중요한 회계추정과 판단
- 같은 제출물에 첨부된 관련 부속자료

따라서 팀에서 `감사보고서`라고 말할 때는 별도 언급이 없는 한 위 전체
패키지를 의미합니다.

## 3. 정보별 기본 원천

| 정보 | 기본 원천 | 비고 |
|---|---|---|
| 사업의 내용 | 사업보고서 | 사업모델·제품·시장 설명 |
| 매출·매입 구조 | 사업보고서 | 품목·지역·고객·원재료 등 |
| 주요 계약 | 사업보고서 또는 해당 수시공시 | 원 접수번호 유지 |
| 감사의견 | 감사보고서 패키지 | 감사보고서 본문 |
| 재무제표 | 감사보고서 패키지 | 감사대상 재무제표 |
| 재무제표 주석 | 감사보고서 패키지 | 사업보고서 주석을 기본값으로 사용하지 않음 |
| 회계정책 | 감사보고서 패키지 | 연결·별도 구분 유지 |
| 중요한 추정·판단 | 감사보고서 패키지 | 원문과 접수번호 유지 |
| 핵심감사사항 | 감사보고서 패키지 | 선정 이유·감사절차 포함 |
| 정정·증자·계약 등 사건 | 해당 수시공시 | 해당 공시가 기본 원천 |

## 4. 원천 우선순위

원천 우선순위(Source Precedence, 같은 내용이 여러 문서에 있을 때 어떤
문서를 먼저 사용할지 정한 순서)는 다음과 같습니다.

1. 재무제표·주석·회계정책·추정 및 감사 관련 정보는 감사보고서 패키지
2. 사업·제품·매출구조·위험·계약 정보는 사업보고서
3. 정정·증자·소송·주요계약 등의 사건은 해당 수시공시
4. 기본 원천을 확보하지 못했을 때만 다른 제출물 또는 요약 캐시 사용

4번을 사용하는 경우 반드시 다음을 표시합니다.

- 실제 사용한 보고서 종류
- DART 접수번호
- 사업연도
- 연결 또는 별도
- 전체 원문인지 일부 원문인지
- 기본 원천을 확보하지 못했다는 제한

## 5. 기존 사업보고서 기반 주석의 처리

현재 코드나 데이터베이스에는 사업보고서에서 추출한 재무제표 주석이 남아
있을 수 있습니다. 이를 레거시 경로(Legacy Path, 과거 구현 때문에 남아
있지만 앞으로 기본 방식으로 확대하지 않을 경로)로 취급합니다.

레거시 자료를 즉시 삭제하지는 않습니다. 다음 순서로 이관합니다.

```text
기존 주석 데이터 현황 조사
→ 실제 원천 보고서와 접수번호 확인
→ 감사보고서 패키지 확보
→ 감사보고서 첨부 재무제표·주석 추출
→ 기존 데이터와 대조
→ 감사보고서 기반 데이터 재생성
→ 미확보·불일치 건 별도 기록
→ 출시용 데이터베이스 재검증
```

이관 전까지 사업보고서 기반 주석을 사용할 경우 사용자 답변에
`사업보고서 기반 대체자료` 또는 이에 준하는 제한을 표시해야 합니다.

## 6. 데이터베이스 접근 원칙

데이터베이스(Database, 수집·가공한 정보를 표 형태로 저장하는 공용
자료함)는 한 명의 관리자가 운영합니다.

- `kj`: 관리용 데이터베이스의 수집·수정·구조 변경·출시를 담당합니다.
- `ye`, `ei`: 공용 데이터베이스를 읽기 전용(Read-only, 조회할 수 있지만
  저장하거나 수정할 수 없는 상태)으로 사용합니다.
- 각 담당자는 테스트용 데이터베이스(Test Database, 개발 중 자유롭게
  만들고 삭제할 수 있는 작은 임시 데이터베이스)와 픽스처(Fixture,
  반복 테스트를 위해 준비한 작은 샘플 문서)를 만들 수 있습니다.
- 공용 데이터 오류는 데이터베이스 행을 손으로 고치는 방식이 아니라
  수집·추출·변환 코드를 수정하고 재생성하는 방식으로 해결합니다.

## 7. 기능 개발 시 필수 확인사항

재무제표·주석·회계정책·KAM 관련 기능을 변경하는 사람은 PR(Pull Request,
변경사항을 검토받아 기본 코드에 합치기 위한 요청)에 다음을 기록합니다.

1. 어떤 DART 제출물을 사용했는가
2. 감사보고서 패키지의 어떤 첨부문서를 사용했는가
3. 연결·별도 중 무엇인가
4. 사업연도와 접수번호는 무엇인가
5. 전체 원문·일부 원문·대체자료 중 무엇인가
6. 기존 사업보고서 기반 데이터가 사용됐는가
7. 실제 원문과 어떻게 대조했는가
8. 어떤 자동 테스트를 실행했는가

## 8. 완료 기준

다음 조건을 만족해야 감사보고서 패키지 기반 기능이 완료된 것으로 봅니다.

- 감사보고서 본문과 첨부 재무제표·주석을 하나의 패키지로 처리함
- 감사보고서 패키지가 있으면 사업보고서 주석보다 우선함
- 원문과 구조화 결과의 접수번호가 일치함
- 연결·별도를 조용히 합치지 않음
- 대체자료를 기본 원천처럼 표시하지 않음
- DART 원문 링크를 제공함
- 자료 미확보를 공시 부재로 단정하지 않음
- 자동 테스트와 실제 공시 대조를 모두 완료함
